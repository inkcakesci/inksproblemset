## 问题

Java 反射有哪些主要缺点？实际框架如何降低这些影响？

## 答案

反射的主要代价包括：

- **类型安全较弱**：方法名、参数或访问权限错误往往到运行时才暴露。
- **性能开销**：元数据查找、动态分派、装箱及访问检查等可能比直接调用成本高，也可能影响部分 JIT 优化。
- **破坏封装**：尝试访问非公开成员会增加耦合；在 Java 模块系统和较新 JDK 中，深度反射还可能受到强封装限制。
- **可维护性较差**：字符串形式的类名或方法名不容易被重构工具可靠追踪。

成熟框架通常缓存反射元数据，避免重复扫描，并使用生成访问器、字节码、Method Handle 或编译期代码生成优化热点路径。反射不应被一概禁止，关键是避免在高频业务循环中无缓存地重复查找和调用。
