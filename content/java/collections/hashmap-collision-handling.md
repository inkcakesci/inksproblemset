## 问题

`HashMap` 发生碰撞后如何保存数据？业务代码可以怎样减少碰撞？

## 答案

JDK 8+ 使用分离链地址法：同一桶中的不同 Key 先组成链表；当桶足够长且数组容量达到要求时，可能转为红黑树，以改善严重碰撞下的查找上界。扩容会增加桶数量，让部分节点分散到新桶，但不能修复质量极差的哈希函数。

业务侧只能减少碰撞，不能保证完全没有：

- 为自定义 Key 实现与 `equals()` 一致、分布良好的 `hashCode()`，让参与相等性的字段共同参与哈希。
- 避免所有对象返回常数、只使用低变化字段，或简单把多个字段相加造成大量对称碰撞。
- 根据预期元素数量合理预设容量，减少负载过高和频繁扩容。
- Key 保持不可变，避免插入后哈希发生变化。
- 对不适合哈希的键空间选择 `EnumMap`、数组、`TreeMap` 等结构。

不要把“扩容、链表、红黑树”称为避免碰撞；它们是降低碰撞概率或控制碰撞成本的机制。
