## 问题

为什么长期记忆提取等耗时 LLM 任务更适合进入持久队列，而不是在 HTTP 请求中直接执行？

## 答案

持久队列把“用户请求已经完成”和“增强任务最终完成”分成两个可靠边界。HTTP 请求只负责提交可追踪的任务，Worker 再异步调用模型；这样模型超时、限流或进程重启不会占住请求线程，也不会让已经提交的聊天失败。

关键不是简单地“改成异步”，而是保证：

- 任务与业务来源具有稳定 ID 和幂等键；
- 入队结果持久化，Worker 可以在崩溃后重新领取；
- 请求端能够接受排队中的最终一致性，而不是立即读到结果；
- 队列不可用时按业务重要性 fail open 或 fail closed，并留下可观测原因。

如果接口入队后又在当前请求中自行认领并执行，它仍然占用请求线程，还可能与后台 Worker 竞争，不能算真正完成了解耦。
