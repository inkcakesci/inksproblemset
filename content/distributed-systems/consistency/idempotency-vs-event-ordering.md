## 问题

消费者已经按 event ID 去重，为什么数据仍可能被旧事件覆盖？

## 答案

幂等解决同一个操作重复执行，顺序控制解决不同操作以错误次序执行。两个 event ID 不同的合法事件都能通过去重，因此还需要聚合版本、generation 和受控状态迁移阻止旧状态覆盖新状态。

### 业务背景

同一条消息的旧 revision 提取任务与编辑后的新任务拥有不同幂等键。即使两者各执行一次，旧任务晚完成仍可能覆盖新事实，所以写入前还要检查 canonical revision，并对当前事实使用版本 CAS。

对检索投影中的同一文档，可以携带单调业务版本，拒绝低版本更新；删除也要进入同一版本序列。若事件是必须逐个执行的增量操作，不能简单忽略所有较旧版本，还需处理缺口和补发。

### 易错点

跨机器时间戳不一定可靠，不能只用“最后到达”或墙上时钟判断业务新旧。
